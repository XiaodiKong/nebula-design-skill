# 主题转译质量门槛

主题转译不是把颜色、字体和圆角覆盖到同一套页面上。它可以改变节奏、组件表面和产品证明方式，但必须保持内容可读、操作可用、几何一致和断点稳定。

## 四层转译

按顺序完成，不能只做第一层：

1. **令牌层**：颜色、字体、圆角、阴影、边界和动效。
2. **组件层**：按钮、导航、卡片、标签、表单和产品证明表面。
3. **布局层**：Hero 比例、内容密度、区块节奏和证明模块的位置。
4. **叙事层**：终端、文档、任务画布、产品界面或案例如何支撑价值主张。

同一多主题 Demo 保持价值主张、内容顺序和 CTA 不变，但允许主题为产品证明选择更合适的布局。

## 可读层不得冲突

- 两个包含正文、标签、按钮或可聚焦控件的层不能在同一区域直接重叠。
- 大标题覆盖背景只适用于低细节图像、视频、纹理或专门简化的静态产品预览。
- 不把完整交互工作台降透明度后放到正文下面；透明度和文字阴影不能修复信息冲突。
- 背景产品预览如果不可操作，应从键盘和辅助技术中移除；如果可操作，必须拥有独立、无遮挡的阅读区域。
- 装饰性伪元素使用 `pointer-events: none`，并且不能遮住焦点环、文本或状态。

## 几何与参考线

- 参考线、网格和边框必须共用页面容器变量，不能分别硬编码近似宽度。
- 参考线应对齐模块外边界、列线或基线；相差几像素的“双线”属于错误，不是细节。
- 页面已有模块边框时，背景参考线降低对比或减少数量。
- 同一区域通常只保留一种主要分隔方式：留白、边框、背景差或阴影。
- 装饰网格的对比度必须低于内容边界，不能与表格、卡片和流程线竞争。

## 字体与断行

- 提示符、编号和 ASCII 标记放在独立元素或绝对定位装饰中，不进入标题文本排版流。
- 中文使用等宽字体时单独检查字宽、标点、英文混排和回退字体。
- 超大中文标题在目标宽度下手动检查断行；不要只依赖 `text-wrap: balance`。
- 品牌的极细拉丁标题不能直接套给中文；中文大标题通常不低于 500 字重。

## 装饰预算

每个首屏确定一个主要视觉机制，例如：

- OpenCode AI：等宽排版 + 命令面板 + 一组容器参考线。
- Palantir：任务画布 + 产品证明 + 克制网格。
- Linear：暗色产品画面 + 柔和光晕。
- Notion：内容排版 + 少量手绘图形。

不要同时叠加高对比网格、双参考线、密集卡片边框、扫描线、玻璃效果和超大标题。

## 响应式门槛

主题专属布局至少检查：

- `1440px`：宽桌面节奏和最大内容宽度。
- `1280px`：常见桌面，重点检查标题和产品证明。
- `1024px`：窄桌面，确认列宽仍能容纳中文和操作。
- `768px`：平板或折叠点，主题专属网格必须正确回到单列。
- `390px`：移动端导航、断行、操作和横向溢出。

主题选择器中的每个主题都要检查首屏、一个内容网格、一个产品证明和页脚，不能只检查默认主题。

## 验收

- 页面无横向溢出，标题无孤立符号和不可解释断行。
- 任意两个可读层没有非预期矩形交叠。
- 参考线与内容容器在至少两个桌面宽度下对齐。
- 背景装饰比正文、控件、状态和焦点环更弱。
- 主题切换不改变内容含义、主 CTA、焦点顺序和交互结果。
- `prefers-reduced-motion` 下仍可完整理解页面。
- 浏览器控制台无错误；键盘可以到达所有可操作内容。
