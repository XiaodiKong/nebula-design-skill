# OpenCode AI 营销页适配

用于 AI 编码、CLI、终端工具、开源开发者产品与用户明确选择 OpenCode AI 风格的营销页面。

## 官方研究来源

- [OpenCode 官网](https://opencode.ai/)
- [OpenCode 文档](https://opencode.ai/docs/)

研究日期：2026-07-30。以下内容是基于公开官网的非官方前端适配。

## 视觉规律

- 当前官网以深黑背景、近白文字和全局等宽字体为主。
- 页面有明确的纵向边界与横向分隔线，圆角极少，像经过排版的终端或技术说明书。
- 首屏直接提供安装命令，并允许在 `curl / npm / bun / brew / paru` 等方式间切换。
- 导航短而直接，下载按钮高对比；文档、模型与企业入口优先于传统营销分类。
- 产品证明使用终端、代码、日志与可复制命令，而不是抽象插图。
- 图形和统计使用图注、编号、ASCII 标记与技术标签增强可信度。

## 营销页实现

- 使用 `#10100f` 左右背景、灰白正文、低对比边框和等宽字体。
- 容器保持硬边或 0–4px 圆角，按钮使用矩形高对比块。
- Hero 先写清产品类别，再提供可复制的快速开始命令。
- 命令切换必须可操作，并提供复制成功反馈。
- 功能列表适合使用 `[ * ]`、编号、终端状态或代码注释建立节奏。
- 中文使用支持汉字的等宽字体回退，避免英文等宽字体缺字后出现严重字宽跳变。
- 桌面首屏可把文案与产品证明并列；不要把完整命令区和完整工作台纵向堆成过长首屏。
- 页面参考线必须复用内容容器宽度变量，并降低到模块边框以下的对比度。
- `>`、`$`、`[*]` 等提示符使用独立元素或定位装饰，不进入中文标题的断行计算。
- 终端感来自排版、命令和信息组织，不需要给每个区块重复增加边框。

## 避免

- 不把等宽风格等同于绿色“黑客终端”。
- 不加入玻璃拟态、柔和卡片或大圆角胶囊。
- 不展示无法执行的命令；示例命令必须标注为演示或替换为真实安装方式。
- 不让参考线与模块边界形成相差数像素的双线。
