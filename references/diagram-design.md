## 基本原则

1. **先关系，后画法**：先确认节点、关系、层级、方向、边界和状态，再选择图库。
2. **结构优先**：布局必须让主要路径、系统边界和异常节点一眼可见。
3. **位置稳定**：刷新、展开和状态变化时尽量保留节点位置，保护空间记忆。
4. **渐进披露**：默认展示主干；通过分组、折叠、聚焦和详情面板承载复杂度。
5. **语义一致**：颜色表达状态，形状或图标表达类型，线型表达关系。
6. **可操作**：交互图必须帮助定位、判断或编辑，不能只是可拖动的装饰。
7. **可替代**：复杂图提供树、列表或表格视图，支持搜索和无障碍访问。

不要把所有关系数据都做成力导向网络图。没有稳定结构和阅读顺序的“毛线团”不是有效架构图。

## 选择正确图型

| 任务 | 首选图型 | 默认方向 | 典型场景 |
|---|---|---|---|
| 展示系统组成与边界 | 分层架构图 | 左→右或上→下 | 应用架构、部署架构 |
| 展示父子和归属 | 层级树 | 上→下 | 组织架构、菜单、分类 |
| 展示步骤与责任 | 流程图 / 泳道图 | 左→右 | 审批、业务流程 |
| 展示依赖与上下游 | 分层 DAG | 左→右 | 数据血缘、任务依赖 |
| 展示设备或服务连接 | 拓扑图 | 分层或中心辐射 | 网络、服务拓扑 |
| 展示按时间发生的交互 | 时序图 | 上→下时间轴 | 服务调用、事件交互 |
| 探索弱层级关系 | 关系网络图 | 力导向或聚类 | 知识图谱、关联分析 |

选择规则：

- 有清晰父子关系：使用树，不使用网络图。
- 有明确处理顺序：使用流程或 DAG。
- 需要表达责任主体：使用泳道。
- 需要表达系统边界：使用嵌套分组。
- 需要表达时间先后和参与者：使用时序图。
- 只有当“关系探索”本身是任务时，才使用力导向图。
- 同一页面不要并列多个表达相同关系的图。

## 选择渲染方式

| 方案 | 使用场景 | 优点 | 限制 |
|---|---|---|---|
| HTML + CSS | 很小的静态层级、卡片关系 | 语义和响应式简单 | 连线与复杂布局能力弱 |
| SVG | 默认方案；静态或中小规模交互图 | 清晰、可样式化、易导出 | 大量节点时 DOM 成本高 |
| Canvas | 中大规模、频繁刷新或拖拽 | 绘制性能好 | 无障碍和命中测试需补充 |
| WebGL | 超大图谱和高频动画 | 大规模性能最佳 | 实现和文字渲染复杂 |
| Mermaid | 文档、说明页、低交互预览 | 文本生成快、便于维护 | 深度交互和品牌定制有限 |
| React Flow 类节点库 | 可编辑工作台、流程和 DAG | 节点编辑、连线和视口能力完整 | 需控制默认视觉与数据模型 |
| D3 类可视化库 | 自定义布局和数据驱动图 | 灵活、布局算法丰富 | 交互与组件架构需自行设计 |

默认决策：

- 用户只要文档中的图：优先 Mermaid 或静态 SVG。
- 用户要求普通 HTML 页面中的专业图：优先 SVG。
- 用户要求拖拽、连线、编辑节点：优先使用仓库已有节点画布库；无现成方案时再选择 React Flow 类方案。
- 用户要求高度定制的树、血缘或关系布局：使用 D3 类布局能力，并由应用组件管理状态。
- 数据量较大或持续刷新：评估 Canvas/WebGL，不强行维持全量 SVG DOM。

节点数量只是参考：约 150 个以内通常适合 SVG；数百到约 1,000 个需要优化 SVG 或 Canvas；更大规模优先 Canvas/WebGL。还要结合连线数量、标签复杂度、设备性能和更新频率实测，不把阈值当硬规则。

## 建立语义数据模型

数据模型与渲染视图分离。至少定义：

```ts
type DiagramNode = {
  id: string;
  kind: string;
  label: string;
  subtitle?: string;
  status?: "normal" | "running" | "success" | "warning" | "error" | "disabled";
  parentId?: string;
  metadata?: Record<string, string | number>;
  ports?: Array<{ id: string; side: "top" | "right" | "bottom" | "left" }>;
};

type DiagramEdge = {
  id: string;
  source: string;
  target: string;
  kind: "dependency" | "data" | "control" | "reference" | "async";
  label?: string;
  status?: "normal" | "active" | "warning" | "error";
};
```

另外单独保存：

- 展开/折叠、筛选、搜索和选中状态。
- 节点位置、视口和布局方向。
- 编辑草稿、校验错误、撤销/重做历史。
- 服务端版本、未保存变更和协作冲突。

稳定使用业务 ID。数据刷新时不能根据数组下标重建节点，否则会造成位置跳动和选择丢失。

## 布局规则

### 通用间距

- 普通节点：约 168×64px；紧凑节点：约 144×48px。
- 同层节点间距：24–40px。
- 层级间距：72–96px。
- 分组内边距：24px；分组标题区至少 32px。
- 连线与节点至少保留 12px 视觉间隙。
- 节点文字默认最多两行，完整内容在详情或 Tooltip 中查看。

根据真实内容调整尺寸，不把所有节点锁死为相同宽度，也不要让单个长标题撑破整个布局。

### 分层架构与 DAG

- 稳定采用左→右或上→下方向。
- 输入/来源放起点，核心处理放中间，输出/消费放终点。
- 同一层节点对齐，减少连线交叉和反向边。
- 边从明确端口进出，优先正交线或平滑折线。
- 环依赖需要单独标识，不能让布局算法假装它不存在。

### 层级树

- 根节点位置稳定，兄弟节点保持业务顺序。
- 默认展开 2–3 层；深层级使用折叠、搜索和面包屑。
- 子节点数量较多时显示聚合节点，如“数据服务（26）”。
- 组织架构中避免用头像大小表达权力或重要程度。

### 流程与泳道

- 主流程沿单一方向，异常和回退分支放在主轴两侧。
- 泳道按角色、系统或阶段划分，只选择一种主要维度。
- 判断节点使用明确问题；分支在线上直接标注条件。
- 避免线从节点正文中穿过，长距离跨泳道连线使用跳线或引用节点。

### 关系网络与拓扑

- 以当前焦点节点或核心服务建立稳定中心。
- 使用聚类和分组控制密度；允许只展开一跳或两跳关系。
- 力导向布局结束后稳定位置，不持续漂移。
- 线路过多时使用边聚合、局部高亮或按类型过滤。

### 增量更新

- 新增节点放在关联节点附近，再执行局部布局。
- 展开分组只移动必要区域。
- 刷新状态不重新计算全图。
- 保存用户手动调整的位置；自动布局前允许恢复。

## 节点、分组与连线

### 节点

节点内容优先顺序：

1. 类型图标或短标识。
2. 主名称。
3. 一项关键副信息。
4. 状态或最多两个短标签。

避免把详情表单塞进节点。选择后在右侧面板显示属性、日志、依赖或操作。

节点状态：

- 默认：白色背景、弱边框。
- 悬停：浅蓝背景或边框增强。
- 选中：主色描边与可见焦点环。
- 运行中：蓝色状态点或轻量流动线，不让整个节点闪烁。
- 成功、警告、失败：使用稳定语义色，并配文字或图标。
- 禁用：降低对比度，同时说明原因。

### 分组与层

- 用带标题的浅背景容器表达系统、网络区、团队或部署区域。
- 嵌套不超过约三层；更深结构使用钻取。
- 分组颜色保持中性，不为每个组随机分配高饱和色。
- 折叠后显示组内节点数、异常数和主要输入输出。

### 连线

默认线宽 1.5px、箭头约 8px：

- 实线：同步调用、主流程或直接依赖。
- 虚线：异步、引用、可选或弱关系。
- 加粗/高亮：当前选中路径或正在流动的数据。
- 错误线：仅对故障路径使用红色，不能全图泛红。

只在标签能消除歧义时标注连线。标签放在线段中间或转折附近，使用浅色底避免被线穿过。不要用十几种线型编码关系。

## 图形工作台

查看型页面推荐：

```text
页面标题 + 范围说明                    [导出] [刷新]
搜索 / 图类型筛选 / 状态筛选 / 环境 / 时间
图例 + 当前筛选摘要
┌───────────────────────────────┬─────────────┐
│ 图形画布                      │ 详情面板    │
│ 缩放 / 适配 / 小地图          │ 属性与操作  │
└───────────────────────────────┴─────────────┘
面包屑 / 节点数 / 连线数 / 更新时间
```

编辑型页面推荐：

```text
资源与节点库 | 可编辑画布 | 属性与校验面板
版本 / 保存状态 / 撤销重做 / 自动布局 / 校验 / 发布
问题列表、运行结果或变更差异
```

图形画布获得最大空间。次要面板可折叠并记忆宽度。空选中时显示全局摘要、图例或操作引导，不显示无意义空白。

## 查看与编辑交互

### 查看型

至少提供：

- 放大、缩小、适配画布、重置视图。
- 搜索节点并定位。
- 按类型、状态、环境或关系筛选。
- 点击节点聚焦并打开详情。
- 高亮上游、下游、最短路径或当前分支。
- 大图提供小地图、层级面包屑和“回到中心”。

鼠标滚轮缩放时避免劫持页面滚动：只有指针位于画布并明确操作时缩放；触控板和键盘行为保持可预期。

### 编辑型

按任务提供：

- 拖拽节点、从端口连线、框选和多选。
- 对齐线、网格吸附、自动布局。
- 复制、粘贴、撤销、重做和删除。
- 键盘移动和连线替代操作。
- 实时校验孤立节点、非法连接、环依赖和缺失配置。
- 未保存提示、版本差异和冲突处理。

删除节点前展示受影响连线和下游。高风险发布必须经过校验与影响确认。

## 状态与反馈

图形页面必须覆盖：

- 加载：使用接近最终结构的节点和连线骨架。
- 空数据：解释为何无节点，并提供创建、导入或调整范围入口。
- 筛选无结果：保留筛选并提供清除。
- 局部失败：保留成功区域，标出失败分组并允许重试。
- 数据过期：显示更新时间和刷新状态。
- 无权限：隐藏敏感节点详情，说明申请路径。
- 布局失败：回退为树、列表或未布局视图，不能显示空白画布。
- 过度密集：进入聚合模式并说明隐藏了多少节点或连线。

自动布局、导出和大规模计算属于长任务时，显示当前阶段和可取消性。

## 响应式与可访问性

- 桌面端优先；画布高度应明确，不能依赖内容把容器撑开。
- 1024px 附近允许折叠详情面板和次要筛选。
- 窄屏默认提供只读图、树或列表；复杂编辑提示使用桌面端。
- 图形容器具有标题、说明和键盘焦点。
- 节点可通过 Tab 或方向键访问；选中状态对屏幕阅读器可见。
- 提供图形摘要，如“6 个系统、18 个服务、2 条故障链路”。
- Canvas/WebGL 图必须同步维护可访问的 DOM 列表或树。
- 颜色不是唯一编码；使用图标、线型、文字和形状辅助。
- 导出 SVG/PNG 时保留标题、图例和必要来源说明。

## 性能与大图降级

- 只渲染视口附近的复杂节点内容。
- 缩小时隐藏次要标签、端口和装饰，保留类型、状态和主路径。
- 对搜索、拖拽和缩放更新节流。
- 大图使用聚类、折叠、层级加载和按需展开。
- 自动布局放入 Worker 或后台任务，避免阻塞主线程。
- 缓存布局结果；只有结构变化才重算全图。
- 为 Canvas/WebGL 建立空间索引，优化命中测试。
- 避免每帧测量大量 DOM 节点。

优先降低信息密度，而不是降低文字清晰度。

## 实现流程

1. 检查项目已有图库、框架、设计令牌和数据接口。
2. 定义节点、关系、分组、状态和稳定 ID。
3. 根据用户任务选择图型、方向和渲染技术。
4. 先用 5–15 个代表性节点验证布局与语义。
5. 建立自动布局、视口、选择、筛选和详情状态。
6. 应用图形令牌并接入页面工具栏、图例和详情面板。
7. 补齐加载、空、失败、权限、过密和布局失败状态。
8. 使用短、长、重复和缺失名称测试节点内容。
9. 使用稀疏、密集、深层和异常关系数据测试布局。
10. 验证键盘、触控板、缩放边界、导出和替代视图。

已有项目使用现有技术栈，不为了套用示例替换图库。新项目先实现最小可用图，再决定是否引入重型渲染或布局依赖。

## 验收清单

- 图型与关系语义匹配。
- 主阅读方向和起点明确。
- 系统边界、层级和异常路径可快速识别。
- 节点无重叠，主要连线不过度交叉或穿过节点。
- 名称截断、极端层级和大量关系有合理处理。
- 缩放、适配、搜索、筛选、聚焦和返回有效。
- 数据刷新不导致全图无意义跳动。
- 编辑操作可撤销，非法连接有明确反馈。
- 状态、权限、失败和大数据量降级完整。
- 键盘、焦点、颜色替代和列表/树替代视图可用。
- HTML 页面在目标宽度下没有画布坍塌或操作遮挡。

## 示例蓝图

### 系统架构图

- 分组：访问层、应用服务层、数据服务层、基础设施。
- 节点：网关、服务、数据库、消息队列、外部系统。
- 连线：同步调用为实线，异步消息为虚线。
- 交互：按环境筛选、聚焦上下游、查看接口和运行状态。
- 右侧详情：负责人、版本、SLA、依赖、告警和变更记录。

### 组织层级图

- 根节点：组织或事业群。
- 层级：部门、团队、岗位或成员。
- 默认展开 2–3 层，显示下级数量和异常状态。
- 搜索结果自动展开祖先路径并定位。
- 提供树列表视图，支持键盘和批量管理。

### 数据血缘图

- 默认左→右：来源表 → 处理任务 → 产出表 → 下游消费。
- 表与任务使用不同图标/形状，状态使用语义色。
- 支持字段级与表级切换，默认先展示表级。
- 点击节点查看上游、下游、字段、质量、负责人和更新时间。
- 影响分析模式只高亮受变更影响路径，折叠无关分支。
