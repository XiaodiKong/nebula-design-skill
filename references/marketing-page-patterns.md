# 营销页面模式

营销页面以理解、信任和转化为主，不按中后台的信息密度组织。先确定受众、核心承诺、证据和唯一主转化目标，再安排版式。

## 页面类型

| 类型 | 主要任务 | 关键区块 |
|---|---|---|
| 首页 / Landing Page | 在短时间内解释产品并引导下一步 | Hero、价值主张、产品证明、场景、社会证明、CTA |
| 功能页 | 解释一项能力如何解决具体问题 | 问题、工作方式、产品画面、收益、集成、CTA |
| 定价页 | 帮助用户选方案并消除购买顾虑 | 套餐、对比、计费说明、FAQ、销售入口 |
| 发布页 | 建立关注并呈现新产品或重大更新 | 发布主张、演示、亮点、时间线、注册或试用 |
| 解决方案页 | 针对行业或角色建立相关性 | 角色痛点、流程、结果、案例、合规或信任信息 |
| 文档 / 开发者入口 | 帮助技术用户快速评估与开始 | 快速开始、代码示例、能力导航、状态、社区入口 |

## 页面骨架

按内容需要选用，不机械堆满所有区块：

1. 顶部品牌导航：Logo、少量一级入口、登录和一个主 CTA。
2. Hero：一句明确价值主张、必要说明、主次 CTA、真实产品证明。
3. 问题与价值：说明目标用户、阻力和可验证收益。
4. 产品能力：围绕用户任务分组，不罗列内部模块。
5. 产品证明：真实截图、交互演示、示例输出或具体工作流。
6. 信任信息：真实客户、案例、合规、安全或可验证指标。
7. 定价与常见问题：只在影响决策时出现。
8. 收尾 CTA 与页脚：重申下一步，提供必要的产品、公司和法律入口。

## 转化层级

- 每页只有一个主转化目标，例如“免费开始”“预约演示”或“加入候补名单”。
- 次操作用于降低承诺，例如“观看演示”“查看文档”，不能和主 CTA 同权竞争。
- 首屏应让目标用户理解“是什么、为谁、解决什么、下一步做什么”。
- CTA 文案描述结果，避免笼统的“了解更多”。
- 长页面在关键证据之后重复主 CTA，但不在每个区块重复。

## 内容与证明

- 使用具体、可验证的业务语言，不使用空泛的“赋能”“领先”“一站式”。
- 不虚构客户 Logo、评价、奖项、合规认证或增长数字。
- 数据未提供时使用结构明确的占位说明，并标注需要真实内容替换。
- 产品截图必须对应真实能力；不要把无关仪表盘当作装饰。
- 复杂产品优先展示一条完整工作流，而不是大量孤立功能卡片。

## 响应式、性能和可访问性

- 顶部导航在窄屏收拢为可操作菜单，主 CTA 保持可见但不遮挡内容。
- 首屏优先加载文字和关键视觉；视频、3D 和重动画提供降级方案。
- 使用语义标题层级、可访问链接与按钮、清晰焦点和足够对比度。
- 尊重 `prefers-reduced-motion`，动画不阻碍阅读与操作。
- 为 SEO 页面提供准确标题、描述、结构化内容和可索引正文；不要把核心文案只放在 Canvas 或图片中。
- 检查 320px 至宽屏的断行、图片裁切、CTA 排列和横向溢出。

## 验收问题

- 首屏五秒内能否说明产品、受众和价值？
- 主 CTA 是否唯一、清楚并可完成？
- 每个重要主张后是否有可信证据？
- 去掉装饰后，内容顺序是否仍能讲完整故事？
- 登录用户是否能清楚进入产品，而公开访客不会误入后台导航？
